# 框架类模板

## 1 从主题定框架（完整填空模板）

用下面这段，把方括号换成用户的实际信息。四段缺一不可。

```text
# 主题描述
请为我设计一份 [核心诉求，如：申请XX项目预算 / 新产品上市 / 年度工作总结]
的 [交付物形态，如：PPT结构框架 / 详细策划方案 / 演讲逐字稿]。

# 背景与人设
我当前的身份是 [职位或角色]，具备 [相关经验 / 目前掌握的核心资源或痛点，
如：5年经验的销售 / 目前面临增长瓶颈]。

# 目标与受众
本次 [汇报 / 演讲 / 方案提交] 的受众是 [目标听众，如：公司大老板 /
跨部门协作团队 / 甲方客户]。
我的核心目标是：向他们证明 / 展示 [核心信息，如：该项目的超高ROI /
我们团队的交付能力 / 新战略的必要性]，
从而最终达成 [期望结果，如：获得50万预算审批 / 拿下项目竞标 /
争取到更多的研发资源]。

# 输出要求与限制条件
- 篇幅 / 时长限制：[如：汇报时长控制在20分钟内 / 总字数不超过2000字]
- 结构 / 格式要求：请构建适合 [使用场景，如：现场高管提案 / 线上快速过会 /
  客户邮件阅读] 的 [具体规格，如：15-20页 / 分5个核心章节] 的详细内容框架
- 风格基调（可选）：请保持 [如：数据导向且逻辑严密 / 充满激情与感染力 /
  严肃客观] 的表达风格
```

用的时候只做两件事：填值、删掉用不到的可选项。

## 2 从文档梳逻辑（完整填空模板）

```text
# 任务描述
我这里有一份关于 [原始文档主题，如：2023年Q3华东区销售项目复盘 /
新款智能音箱上市营销策划 / 年度个人述职] 的文档。
请严格基于我提供的文档内容，为我提炼并生成一套完整的汇报 PPT 详细框架。

# 逻辑要求
在整体内容的组织上，请严格采用 [经典逻辑模型，如：SCQA四段式 /
三层金字塔结构 / STAR面试法则 / 5W1H分析法] 来串联整个大纲：
[模型拆解1，如：S（情景）：铺垫共识性背景 / 现状...]
[模型拆解2，如：C（冲突）：抛出核心矛盾 / 痛点...]
[模型拆解3，如：Q（问题）：点出待解决的关键命题...]
[模型拆解4，如：A（解答）：给出具体的执行方案 / 结论...]

# 细节要求
- 每一页 PPT 都必须使用「结论型标题」（标题本身就是一句话总结，
  而不是「项目背景」这种虚词）。
- 每页正文提炼为 [3-5个] 核心要点（Bullet Points），语言精炼、客观、
  数据导向，适合页面展示，剔除冗长的修饰词。
- 在适合使用图表展示数据或逻辑的页面，标注 [建议配图：xxx]，
  例如「建议配趋势折线图」或「建议配漏斗图」。
```

没有明确模型时的替代句：

```text
请采用「背景现状 - 核心问题 - 解决方案 - 预期收益」的逻辑线来组织大纲。
```

## 3 四种结构模型与选型

| 模型 | 逻辑链 | 适用场景 | 关键要素 |
| --- | --- | --- | --- |
| 金字塔结构 | 结论先行，以上统下，归类分组，逻辑递进 | 整体框架搭建、复杂方案汇报（年度计划、项目提案） | 顶层核心结论；中层 3–5 个支撑论点；底层每论点的论据（数据 / 案例 / 流程） |
| SCQA | 情境 → 冲突 → 问题 → 答案 | 开场引入、章节过渡（方案开场、痛点分析） | S 铺垫共识性背景；C 抛出矛盾 / 痛点；Q 提出待解决的核心问题；A 给出核心方案 |
| PREP | 观点 → 理由 → 例证 → 重申观点 | 短篇幅论证（推荐方案、选择理由、立场表达） | P 明确核心观点；R 给 2–3 个支撑理由；E 用数据 / 案例佐证；P 重申观点 |
| STAR | 情境 → 任务 → 行动 → 结果 | 案例讲解、项目汇报、经验分享 | S 描述背景情境（时间 / 问题）；T 明确核心任务（目标）；A 拆解行动步骤；R 呈现结果（数据 + 价值） |

选型口诀：整篇讲框架用金字塔，开头抓注意力用 SCQA，单点说服用 PREP，讲一个具体案例用 STAR。四者不互斥——常见组合是整篇金字塔，每章内部用 SCQA 起头、用 STAR 讲故事。

## 4 极简收敛指令（实战版，三段够了）

需求已经聊清楚、只差一版成稿时，不用四段式，三行就够：

```text
汇报背景：我是一名[15年经验的程序员，产品是自己做的]。
汇报目标：[产品发布时，准备试用的用户、以及运营和推广同事]。
输出要求：汇报时长[15分钟]左右，请为我构建适合演讲的[10页]PPT详细内容框架和文案。
```

三行分别锁住：说话人是谁（决定能不能讲「我们」）、台下是谁（决定详略和术语）、说多久（决定页数）。**「框架和文案」要一起要**——只给框架，回来的是标题党；要文案，才会逼出每一页的结论句。

## 5 已经想好结构：直接给清单

结构和页序都定了，别让模型再「规划」一遍，直接钉死：

```text
帮我生成一份[麒麟西瓜]品牌计划书PPT，结构包含：封面、执行摘要、市场洞察、
品牌定位、产品矩阵、渠道策略、营销推广、供应链、财务预测、风险控制、封底。
```

这种给法出的东西最稳：章节一个不多一个不少，模型只填内容不重排结构。

## 6 先要一版大纲再收敛

不确定要几页、担心方向跑偏时，第一步只问一句：

```text
帮我生成10页的PPT，分析[TRAE Work]这款产品。
```

看它的章节切分对不对，对了再在同一个会话里补 §4 的三段式细化；不对就换角度重来，比直接生成整份再改便宜得多。
